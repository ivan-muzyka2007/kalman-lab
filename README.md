# kalman-lab
## Описание проекта
Проект первых 12 недель: **от анализа логов полётного контроллера до собственного фильтра Калмана на реальных данных.**

Это каркас репозитория. Он специально почти пустой: код здесь нужно писать вам, а не копировать. Файлы в `src/` — рабочие заготовки и примеры, которые надо прочитать, запустить и переписать под себя.

---

- [ ] `src/logdata.py` — модуль чтения `.BIN`-логов ArduPilot и выгрузки в DataFrame/CSV

## Как начать (неделя 3)

```bash
# 1. окружение
source ~/projects/uavenv/bin/activate

# 2. проверка, что всё на месте
python src/check_env.py

# 3. скопировать свежий лог SITL в data/ (пример)
find ~/ardupilot -name "*.BIN" -mmin -240
cp ~/ardupilot/ArduCopter/logs/test1/<дата>/00000001.BIN data/

# 4. посмотреть, какие записи есть в логе
python src/logdata.py data/00000001.BIN --list

# 5. первые графики
python src/plot_basic.py data/00000001.BIN --out figures/week3_basic.png
```

## Соглашения проекта

1. **Единицы измерения.** Переводить `TimeUS` (микросекунды) в секунды сразу при чтении; углы — как в логе (для ArduPilot это обычно градусы, проверьте!), ускорения — м/с². **Всегда проверяйте единицы эмпирически** (например, сравните `AccZ` в покое: ожидаемое ≈ +9.8 м/с² с учётом знака).
2. **График = доказательство.** Каждое утверждение в отчёте должно опираться на график или число, а не на «кажется, лучше».
3. **Метрики обязательны.** Для любой оценки: RMSE, максимальное отклонение, поведение при выбросах. Сравнивать всегда с эталоном (сырое измерение / штатный фильтр / синтетическая истина).
4. **Раздел «Ограничения» обязателен** в каждом отчёте и в README. Где ваше решение ломается? При каких условиях?
5. **Логи не коммитим.** `.gitignore` уже настроен. Для чужих данных — ссылка на источник в README.
